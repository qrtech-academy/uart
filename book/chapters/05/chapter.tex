\chapter{The Register Bank}
\label{c5:ch}

{\large\itshape Ports become registers; the FPGA half is complete.\par}

\begin{chapterbox}{In this chapter}
\begin{itemize}
  \item \textbf{The two FIFOs from \chapref{4}}, one per direction, instantiated by the bank rather
    than by the top.
  \item \textbf{The register bank} (\code{uart_regs.vhd}) around them: \code{STATUS} computed
    straight from the FIFO flags, the \code{ERROR_FLAGS} latches, \code{CTRL} and \code{BAUD_DIV} as
    plain storage, the write-triggered \code{TX_DATA} push, and the read-then-pop RX path in which
    \code{RX_DATA} is a pure read and \code{RX_POP} is the separate, abort-safe write that advances
    the FIFO.
  \item \textbf{Completing \code{uart_top}}: instantiating \code{uart_regs}, which owns both FIFOs,
    into the skeleton from \chapref{1}, the last block it was waiting for, so the full system
    testbench runs for the first time.
\end{itemize}
\end{chapterbox}

This chapter is about the distance between port semantics and register semantics. The TX and RX
cores speak in pulses and levels, while the register map (\secref{proto:part2}) promises poll-able
bits, sticky error flags and FIFO-backed data; bridging the two is the whole job. After the chapter
you should be able to explain why a single-cycle error pulse cannot be polled, and implement
pulse-to-level latching with a defined set and clear pair for each \code{ERROR_FLAGS} bit, while
deriving every \code{STATUS} bit combinationally from the FIFO flags instead; explain why popping a
FIFO on read would need write-like commit-and-abort discipline, and why splitting the pure read
(\code{RX_DATA}) from the explicit pop (\code{RX_POP}) avoids it; and instantiate the register bank
into \code{uart_top} positionally, completing the peripheral so that it passes the system
testbench.

\textbf{Before you start}, you need what \chapref{1} started: the \code{uart_top} skeleton and the
\code{uart_def} package. You need the datapath blocks \code{baud_gen}, \code{uart_tx} and
\code{uart_rx} from Chapters~2 and~3, along with the pulses and levels they expose, wired into the
top across Chapters~2 and~4, and the \code{fifo} from \chapref{4}, which this bank instantiates
twice. Read the whole protocol (Appendix~\ref{proto:ch}) first, especially the register semantics
(\secref{proto:semantics}) and the SPI transport (\secref{proto:part3}), which you instantiate but
do not write.

Read \secref{c5:sec:uart_regs} for \code{uart_regs}; that is the specification you build it from.
The two FIFOs it owns were built in \chapref{4} and are already in \file{hw/}. Revisit
\secref{c1:app:b} for the top you now complete. Then read the provided testbench
\file{hw/uart_regs_tb.vhd}, along with the system testbench \file{hw/uart_top_tb.vhd}, which plays
SPI transactions through the provided transport and watches a byte cross the whole peripheral.

The two ideas of the chapter are \code{STATUS} computed straight from the FIFO flags rather than
stored, and the \code{RX_DATA} and \code{RX_POP} split with the reasoning behind it. The rest of the
register decode is seven near-identical cases, and the \code{ERROR_FLAGS} latch is one more. With
\code{uart_regs} instantiated into \code{uart_top}, every block is present, and the system testbench
elaborates and runs for the first time, which is the moment the FPGA half becomes a thing that
works:

\begin{shell}
make build-vhdl   # From the repository root: every testbench whose modules exist.
\end{shell}

\noindent In the exercises in \secref{c5:sec:exercises} you build \code{uart_regs}
(Exercise~\ref{c5:ex:1}), then instantiate the bank into the \code{uart_top} skeleton, delete the
\code{reg_rdata} placeholder you left there in part~d) of Exercise~\ref{c1:ex:2}, and run the full
system testbench (Exercise~\ref{c5:ex:2}).
